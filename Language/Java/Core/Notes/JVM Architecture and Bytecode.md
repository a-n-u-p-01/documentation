### What is JVM?

The **Java Virtual Machine (JVM)** is an abstract engine that runs Java bytecode, making Java platform-independent by allowing compiled programs to run on any device with JVM.

---

### Key Responsibilities

- **Load and verify bytecode**
- **Manage memory** (heap, stack, etc.)
- **Execute bytecode**
- **Provide runtime services** (garbage collection, multithreading)
- **Ensure security and platform independence**

---

### JVM Architecture

#### 1. **Class Loader Subsystem**
- Loads `.class` files into memory.
- Phases: **Loading**, **Linking**, **Initialization**.
- Types of Class Loaders: **Bootstrap**, **Extension**, **Application**.

#### 2. **Runtime Data Areas**
- **Method Area**: Stores class-level data.
- **Heap**: Stores objects, subject to garbage collection.
- **Java Stack**: Method call frames for each thread.
- **PC Register**: Points to the current instruction for each thread.
- **Native Method Stack**: Supports native (non-Java) methods.

#### 3. **Execution Engine**
- **Interpreter**: Executes bytecode line-by-line (slower).
- **JIT Compiler**: Converts hot bytecode to native code (improves performance).
- **Garbage Collector**: Removes unused objects from the heap.

#### 4. **Java Native Interface (JNI)**
- Allows Java to call native methods (C/C++) for system-level operations.

#### 5. **Native Method Libraries**
- External libraries used by JVM to execute native methods.

---

### Bytecode in Java

- **Bytecode**: Platform-independent code generated by the compiler (`javac`), stored in `.class` files.
- It's interpreted by the JVM or compiled into native machine code by the JIT compiler.

---

### JVM vs JRE vs JDK

- **JVM**: Executes bytecode.
- **JRE**: JVM + core libraries.
- **JDK**: JRE + development tools (compiler, debugger).

---

### Summary

- JVM executes Java programs, manages memory, and provides services like garbage collection.
- Makes Java platform-independent using bytecode.
- Essential for writing efficient, scalable, and secure Java applications.
